# Avalanche Simulation — C++

A real-time 2D simulation of snow and rock particles flowing down a mountain landscape.

The project models the interaction between particles, terrain obstacles and emission sources while providing a real-time graphical visualization. It is implemented in modern C++ using object-oriented design and [Raylib](https://www.raylib.com/) for rendering.

## Overview

The simulation represents a mountain environment populated by different types of particles.

Snow and rock particles are continuously generated by sources and move through the environment according to their physical and interaction rules. Obstacles influence their trajectories, allowing avalanche-like flows to emerge naturally from the local interactions between particles and the terrain.

The simulation is designed around an object-oriented architecture where the main physical entities are represented by independent classes.

## Architecture

The simulation is divided into several layers.

### Particles

`Particule` provides the common behaviour shared by particles in the simulation.

Specialized particle types extend this base class:

* `ParticuleNeige` — snow particles
* `ParticuleRoche` — rock particles

This inheritance-based structure makes it possible to add new particle types without redesigning the simulation engine.

### Environment

The environment is represented by the `Systeme`, `Case` and `Obstacle` classes.

The system manages the simulation state, while obstacles define the geometry that particles interact with.

### Sources

`Source` objects are responsible for generating particles and introducing them into the simulation.

This makes particle generation independent from the rest of the simulation logic.

### Rendering

Rendering is separated from the simulation logic through the drawing-related interfaces and classes.

Raylib is used only for the graphical layer, keeping the core simulation relatively independent from the rendering implementation.

## Performance

Particle simulations can become computationally expensive because each particle may need to interact with nearby particles and obstacles.

To reduce unnecessary calculations, the simulation uses a **spatial partitioning approach**.

Instead of comparing every particle with every other particle, the environment is divided into spatial cells. Particles only need to consider objects located in nearby cells.

This reduces the number of unnecessary interaction checks and allows the simulation to remain responsive as the number of particles increases.

Conceptually, a naive approach can approach:

```text
O(n²)
```

for pairwise particle interactions.

Spatial partitioning significantly reduces the number of comparisons required in practice by restricting interactions to local neighbourhoods.

## Requirements

To build the project, you need:

* A C++ compiler supporting C++17
* CMake 3.15 or newer
* Raylib
* Make (optional, if using the Makefile)

The project has been developed with macOS/Linux-style command-line environments in mind.

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/avalanche-simulation-cpp.git
cd avalanche-simulation-cpp
```

Replace `YOUR_USERNAME` with your GitHub username.

### 2. Build with CMake

Create a build directory:

```bash
mkdir build
cd build
```

Configure the project:

```bash
cmake ..
```

Compile:

```bash
cmake --build .
```

### 3. Run

From the `build` directory:

```bash
./avalanche_simulation
```

If the executable is generated in a different location by your platform or generator, run the corresponding executable from the build directory.

## Building with Make

If Raylib and the required dependencies are already installed, the provided Makefile can also be used:

```bash
make
```

Then run:

```bash
./avalanche_simulation
```

To remove compiled files:

```bash
make clean
```

## Simulation Workflow

At a high level, each simulation frame follows this process:

```text
Generate particles
       ↓
Update particle states
       ↓
Detect nearby objects
       ↓
Apply interactions
       ↓
Update positions
       ↓
Render environment
       ↓
Next frame
```

The simulation continuously repeats this process while the graphical application is running.

## Design Principles

The project focuses on several software engineering principles:

### Object-oriented design

Simulation entities are represented by dedicated classes with clearly defined responsibilities.

### Separation of concerns

Simulation, particle behaviour, environment management and rendering are kept as separate components.

### Extensibility

The architecture makes it possible to introduce additional particle types, obstacles or behaviours without rewriting the entire simulation.

### Performance-aware design

Spatial partitioning is used to avoid unnecessary calculations when handling large numbers of particles.
